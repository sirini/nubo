# NUBO v1.2.27

NUBO v1.2.27은 실제 서비스에서 발견한 advance 블로그·갤러리의 사용성을 다듬고, 모든 게시판
스킨의 작성 경험을 하나의 플랫폼 공용 Tiptap 에디터로 통합한 릴리스입니다. 제한된 사내망에서의
수동 실행과 하위 경로 배포도 정식으로 문서화하고 지원합니다.

## 주요 변경사항

### 모든 게시판 스킨이 사용하는 공용 Tiptap 에디터

- 기본 board/blog/gallery/trade와 advance blog/gallery의 작성·수정 본문이 플랫폼 공용
  `NuboTiptapEditor`를 사용합니다.
- 표 삽입과 행·열 편집, 링크, 본문 이미지, 글자색, 코드 블록, Markdown 붙여넣기와 이미지
  드래그·붙여넣기를 모든 게시글 스킨에서 동일하게 제공합니다.
- advance gallery의 일반 텍스트 입력란을 HTML 호환 리치 에디터로 교체해 기존 서식 글도 안전하게
  수정할 수 있습니다.
- 스킨별로 복제돼 있던 Tiptap·표·링크·이미지 업로드 구현을 제거했습니다. 새 스킨 제작자는 공용
  컴포넌트 하나를 배치하고 목록·상세·작성 화면의 디자인에 집중할 수 있습니다.

### advance 블로그·갤러리 실사용 개선

- 블로그 읽기 진행률을 viewport 최상단에 고정해 스크롤 중 어중간한 위치로 움직이지 않습니다.
- 두 advance 스킨의 수정 링크를 실제 `/edit` 라우트와 일치시켰습니다.
- 갤러리 전체 화면의 좌우 탐색 버튼과 클릭 영역을 키워 이미지 확대와 탐색이 충돌하지 않게 했습니다.
- 1:1 원본 보기는 중앙에서 시작하며 스크롤과 마우스 드래그로 큰 이미지의 원하는 위치를 탐색할 수
  있습니다.
- Pretendard 가변 폰트의 굵기 축을 400으로 고정하던 전역 선언을 제거해 한글 굵게 서식이 정상적으로
  표시됩니다.

### 제한망 수동 실행과 하위 경로 배포

- `npm run server:manual`은 외부에서 반입한 공식 bundle과 SHA-256을 검증하고 GOAPI 바이너리와
  libvips를 소스 checkout에 준비합니다.
- `.env`를 명시한 GOAPI 실행과 `node .output/server/index.mjs`를 이용한 Nuxt 수동 실행 절차를
  README에 추가했습니다.
- `NUXT_APP_BASE_URL=/sample/`처럼 하위 경로를 지정하면 SSR, 정적 asset, 브라우저 API,
  원본 이미지·첨부 다운로드와 nuboctl 상태 확인이 같은 경로를 따릅니다.
- `app.baseURL`의 기본값 `/`와 제목 템플릿을 명시했습니다.

### 게시판 그룹 설정 안정화

- 관리 화면에서 게시판을 직접 수정할 때 비동기 그룹 목록보다 먼저 UID 0이 저장되던 문제를
  바로잡았습니다.
- NUBO는 게시판 설정의 실제 `groupUid`를 유지하고, GOAPI는 존재하지 않는 그룹이나 게시판
  ID–UID 불일치를 거부합니다.
- 새 DB는 기존 첫 그룹을 재사용하고 그룹이 하나도 없을 때만 기본 `boards` 그룹을 만듭니다.

### 공식 Market 스킨 갱신

- 기본 게시판 0.2.1, 기본 블로그 0.1.2, 기본 갤러리 0.1.2, 기본 중고거래 0.1.4가 공용 에디터를
  사용하는 새 Market 버전으로 제공됩니다.
- advance blog 0.1.0과 advance gallery 0.2.0을 Market에 처음 공개합니다.
- 공용 에디터가 플랫폼에 포함된 NUBO 1.2.27 이상에서 새 버전들을 설치할 수 있습니다.

## 업데이트 방법

공식 systemd 설치를 사용 중이라면 다음 순서로 계획과 상태를 확인합니다.

```bash
nuboctl update --dry-run
nuboctl update
nuboctl status
```

사이트 전용 스킨이나 Market 스킨을 사용한다면 update가 새 공식 릴리스를 기준으로 커스텀 Web을
다시 빌드합니다. 직접 적용할 때는 다음 명령을 사용할 수 있습니다.

```bash
nuboctl customize --dry-run
nuboctl customize
```

제한망에서는 외부에서 공식 asset과 `.sha256` 파일을 함께 반입한 뒤 README의 `server:manual`
절차를 따르세요. 검증을 생략한 바이너리나 라이브러리 복사는 공식 설치 절차가 아닙니다.

## 지원 범위

- 공식 prebuilt: Ubuntu 22.04 이상 amd64, Node.js 22 이상, systemd, Nginx, MySQL/MariaDB 단일 서버
- Nginx HTTP 설정은 nuboctl이 지원하지만 TLS 인증서와 외부 DB·메일 제공자 설정은 운영자 영역입니다.
- 데이터베이스와 업로드 파일의 자동 백업·복원은 제공하지 않습니다.
