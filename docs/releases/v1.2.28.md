# NUBO v1.2.28

NUBO v1.2.28은 설치와 업데이트 과정에서 운영자 소유 Nginx 설정을 침범하던 문제와, 실패한
커스텀 Web 후보가 `/opt/nubo/releases`에 계속 누적되던 문제를 바로잡는 긴급 운영 hotfix입니다.

## 주요 변경사항

### Nginx와 TLS는 운영자가 전적으로 관리

- `nuboctl install`은 `/etc/nginx`를 읽거나 설정 파일·심볼릭 링크를 생성·수정하지 않습니다.
- 기존 도메인 설정이나 끊어진 `sites-enabled` 링크가 있어도 NUBO 애플리케이션 설치를 중단하지 않습니다.
- Nginx 활성화·reload를 수행하던 `activate-nginx` 명령과 설치 전용 Nginx 옵션을 제거했습니다.
- NUBO는 systemd 서비스와 내부 `3000`·`3006` 포트의 readiness까지만 책임지며, 공개 프록시와
  인증서는 운영자가 기존 서버 구성에 맞춰 관리합니다.

### 실패한 릴리스 후보 자동 정리

- update는 공식 버전 전환이 성공한 뒤에만 커스텀 Web을 `/opt/nubo/releases`에 배치합니다.
- update/customize가 실패하거나 취소되거나 dry-run으로 끝나면 이번 실행이 새로 만든 공식·사이트
  후보를 자동으로 정리합니다.
- `current` 또는 `previous`가 참조하는 릴리스와 실행 전에 이미 존재하던 릴리스는 항상 보존합니다.
- `/opt` 배치는 임시 디렉터리에 복사와 소유권 설정을 마친 뒤 원자적으로 이동해 불완전한 최종
  디렉터리가 남을 가능성을 줄였습니다.

## 업데이트 방법

공식 systemd 설치에서 다음 순서로 실행합니다.

```bash
nuboctl update --dry-run
nuboctl update
nuboctl status
```

DB와 업로드 백업 질문은 GOAPI 출처가 변경될 때 표시됩니다. 백업을 완료했다면 Enter로 진행하고,
취소하려면 아무 문자열을 입력합니다. 커스텀 스킨을 사용 중인 사이트는 공식 릴리스 전환 뒤 새
버전 기준 Web을 자동으로 빌드·적용합니다.

기존에 누적된 릴리스는 현재·직전·공식 기반 보호 대상을 먼저 확인한 뒤 정리합니다.

```bash
nuboctl releases prune --dry-run
sudo nuboctl releases prune
```

## 지원 범위

- 공식 prebuilt: Ubuntu 22.04 이상 amd64, Node.js 22 이상, systemd, MySQL/MariaDB 단일 서버
- Nginx 또는 다른 reverse proxy와 TLS 설정은 운영자 책임입니다.
- 데이터베이스와 업로드 파일의 자동 백업·복원은 제공하지 않습니다.
