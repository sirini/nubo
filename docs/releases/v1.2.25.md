# NUBO v1.2.25

NUBO v1.2.25는 v1.2.10 이후 진행한 계정 안전성, 통합 릴리스, NUBO Market 연동과 스킨 제작 환경 개선을 한 번에 정리한 릴리스입니다. 직접 서버를 운영하는 작은 커뮤니티가 업데이트와 사이트 꾸미기를 더 예측 가능하게 수행하고, 다른 제작자의 스킨을 안전하게 설치·검증할 수 있는 기반을 완성하는 데 초점을 맞췄습니다.

## 주요 변경사항

### 더 안전해진 계정과 커뮤니티 운영

- 게시글 이동 화면과 API 계약을 정리해 운영자가 게시물을 다른 게시판으로 안전하게 옮길 수 있습니다.
- NUBO와 GOAPI가 같은 API contract를 사용하는지 빌드와 실행 시점에 확인합니다. 호환되지 않는 조합은 상태 화면과 릴리스 게이트에서 조기에 발견합니다.
- 웹에서 계정 삭제를 요청할 수 있고, 신고와 사용자 차단을 서로 다른 기능으로 분리했습니다.
- 공개 이용약관과 커뮤니티 운영 정책을 제공하며, 계정 삭제·신고·차단의 경계를 명확히 했습니다.
- Android 앱을 위한 Google ID token audience 분리, Firebase Installation ID 기반 푸시 등록과 토큰 회전 계약을 추가했습니다.

### 검증된 통합 릴리스

- NUBO와 고정된 GOAPI commit, Nuxt prebuilt, nuboctl, 두 종류의 libvips를 하나의 Linux amd64 릴리스로 계속 제공합니다.
- API contract, NUBO test·lint·typecheck·production build, Ubuntu 22.04 환경의 GOAPI test·vet를 하나의 릴리스 게이트에서 검사합니다.
- Ubuntu 22.04와 24.04의 깨끗한 환경에서 실제 install·systemd·readiness를 확인한 후보만 GitHub Release로 게시합니다.
- 릴리스 manifest에 NUBO·GOAPI 버전과 commit을 기록하고 `/version`에서 실행 중인 조합과 문제를 확인할 수 있습니다.
- 무거운 통합 빌드와 hosted fresh-install 검증을 분리해 공식 릴리스의 재현성과 게시 안정성을 높였습니다.

### 예측 가능한 update와 사이트 꾸미기

- `nuboctl update`가 소스 checkout을 안전한 fast-forward로 갱신하고 공식 릴리스 전환까지 수행합니다. 로컬 충돌이나 갈라진 이력이 있으면 덮어쓰지 않고 중단합니다.
- 한 번 적용한 사이트 전용 스킨은 이후 update에서 새 공식 버전을 기준으로 미리 typecheck·build한 뒤 자동 재적용합니다.
- 이전·새 릴리스의 GOAPI commit이 같으면 DB migration과 백업 확인 질문을 생략하고 Web 중심으로 전환합니다.
- `current` 전환 직전의 릴리스를 `/opt/nubo/previous`에 원자적으로 기록해 복구 기준을 분명히 했습니다.
- `nuboctl releases list`, `releases prune --dry-run`, `releases prune`으로 오래된 릴리스를 안전하게 확인하고 정리할 수 있습니다. current·previous·현재 커스텀 빌드의 공식 기반·최신 예비본은 항상 보호합니다.
- nuboctl 0.14.1은 `customize`와 update의 커스텀 Web 빌드에 Node heap 1536 MiB 기본값을 적용합니다. 운영자가 이미 지정한 `NODE_OPTIONS`는 그대로 우선합니다.

### NUBO Market과 스킨 설치 흐름

- `nuboctl market search`, `info`, `install`로 공식 Registry의 스킨을 찾고 checksum·호환 버전·압축 경로를 검증한 뒤 로컬 소스에 설치할 수 있습니다.
- 설치한 패키지는 package identity와 파일별 SHA-256 영수증을 남깁니다. `market remove --dry-run`과 `market remove`는 설치 파일이 영수증과 모두 일치할 때만 삭제합니다.
- 한글 이름과 긴 설명이 있는 Market 결과를 터미널 폭에 맞춰 정렬하고, TTY 색상·정보 구획·다음 단계 안내를 보강했습니다.
- 기본 홈과 관리 화면에서 공식 NUBO Market, 검색·설치·삭제 명령, `customize` 적용 흐름을 확인할 수 있습니다.
- 스킨 manifest에 1280×720 대표 이미지와 선택 스크린샷 계약을 추가해 Market에서 설치 전에 실제 화면을 확인할 수 있게 했습니다.

### 독립적으로 확장할 수 있는 기본 스킨

- 기존 `nubo-basic-board`에 함께 있던 게시판·블로그·갤러리를 `nubo-basic-board`, `nubo-basic-blog`, `nubo-basic-gallery`로 분리했습니다.
- 각 스킨은 목록·보기·쓰기·수정 UI를 자기 폴더에 직접 소유하며 다른 스킨의 소스 파일을 import하지 않습니다.
- 분리 전 `nubo-basic-board`를 사용하던 기존 블로그·갤러리는 호환 연결을 통해 업그레이드 전후 화면을 유지합니다.
- 각 게시판 계열 스킨에 엔트리 구조, provider로 전달되는 값과 함수, 복사·확장 방법을 설명하는 README와 코드 주석을 추가했습니다.
- 공용 경계는 NUBO provider·store·타입과 플랫폼 UI 컴포넌트로 제한해 제작자가 스킨 하나만 복사해 시작할 수 있습니다.

## 업데이트 방법

공식 설치를 사용 중이라면 NUBO checkout에서 다음 순서로 확인하고 업데이트합니다.

```bash
nuboctl update --dry-run
nuboctl update
nuboctl status
```

사이트 전용 스킨을 수정했다면 별도 heap 설정 없이 다음 명령을 사용할 수 있습니다.

```bash
nuboctl customize --dry-run
nuboctl customize
```

오래된 릴리스는 자동 삭제하지 않습니다. 먼저 보호 대상과 예상 확보 공간을 확인한 뒤 직접 실행하세요.

```bash
nuboctl releases list
nuboctl releases prune --dry-run
nuboctl releases prune
```

## 운영 범위

- 데이터베이스와 업로드 파일의 백업·복원은 NUBO가 자동 수행하지 않습니다. 운영 환경과 보존 정책에 맞춰 운영자가 외부 백업을 관리해야 합니다.
- Nginx HTTP 활성화는 nuboctl이 지원하지만 Certbot 설치, TLS 인증서 발급·갱신과 HTTPS 전환은 운영자 영역입니다.
- 외부 DB와 메일 제공자의 계정·네트워크·도메인 설정은 각 서비스의 운영 절차를 따릅니다.
- 공식 prebuilt 지원 범위는 Ubuntu 22.04 이상 amd64, Node.js 22 이상, systemd, Nginx, MySQL/MariaDB 단일 서버입니다.
