# NUBO v1.3.0

NUBO v1.3.0은 서버 운영과 스킨 생태계의 책임을 분리한다. `nuboctl`은 준비된 릴리스 적용과 진단에
집중하고, 독립 `nubo-market`은 빌드나 프로세스 재시작 없이 스킨 소스만 관리한다.

## Market

- 공식 릴리스와 Source Mode에 `nubo-market 0.1.0` 진입점을 추가했다.
- `diff`로 설치 영수증 이후 수정·추가·누락 파일을 확인할 수 있다.
- `update`는 로컬 변경이 전혀 없을 때만 새 패키지를 검증해 원자적으로 교체한다.
- 다운로드 중 파일이 바뀌어도 실제 전환 직전 재검사해 덮어쓰지 않는다.
- `fork OLD NEW`는 수정본을 사이트 소유 key로 복사하고 원본 key·version을 기록한다.
- update, remove와 fork에는 로컬 변경을 무시하는 `--force`가 없다.
- 설치·교체·삭제 뒤 빌드와 Node·PM2·systemd·tmux 재시작은 운영자가 명시적으로 수행한다.

## 서버 운영

- `nuboctl 0.15.0`의 기본 도움말을 `status`, `doctor`, `apply` 중심으로 줄였다.
- `nuboctl apply <릴리스-디렉터리>`는 대상 경로를 필수로 받고 다운로드·Git·Nuxt 빌드를 하지 않는다.
- `npm run server:stage`는 공식 asset을 다운로드·검증·배치하되 서비스를 바꾸지 않는다.
- 제한망에서는 `server:stage -- --archive ... --checksum ...`으로 같은 검증 경계를 사용한다.
- 설치와 update는 `/usr/local/bin/nubo-market` 링크도 현재 릴리스를 따라가게 관리한다.
- 기존 update, customize, market과 skin 명령은 이전 자동화 호환을 위해 유지한다.

## Source Mode

- `server:prepare`와 `server:manual`이 `./goapi-linux`와 `./nubo-market`을 함께 준비한다.
- 스킨을 바꾼 뒤 `npm run build`하고 운영자가 기존 방식으로 프로세스를 재시작하는 흐름을 공식 문서화했다.
- README를 공식 릴리스와 Source Mode, Market의 신뢰 경계를 중심으로 간결하게 다시 구성했다.

## 갤러리와 이미지 설명

- advance gallery에서 큰 화면의 사진은 고정하고 우측 상세 패널의 본문·해시태그·댓글만 스크롤한다.
- 본문의 해시태그를 표시하고 검색 링크로 연결했으며 목록 보기 버튼의 경계를 분명하게 다듬었다.
- 태그 검색 SQL 오류를 수정하고 `#태그` 입력과 존재하지 않는 태그를 안전하게 처리한다.
- 새 이미지에는 GPT-5.6 Luna가 생성한 한국어 설명과 검색어를 저장하고, basic/advance gallery에서 설명을 표시한다.
- 이미지 설명을 목록 검색에 포함해 `해변`, `노을` 같은 설명 단어로 사진을 찾을 수 있다.
- 기존 첨부 이미지 중 설명이 없는 대상을 비용 안내와 명시적 확인 후 처리하는
  `share/tools/backfill_image_descriptions.py` 운영 도구를 bundle에 포함한다.

## 버전과 검증

- NUBO와 GOAPI 통합 버전을 `1.3.0`으로 맞췄다.
- 릴리스 manifest에 `nubo-market` 구성 요소와 실행 진입점을 기록한다.
- 공식 bundle과 fresh-install smoke가 두 CLI의 실행·설치 링크를 함께 검사한다.

## 업데이트

저장소를 갱신한 뒤 공식 asset을 준비하고, 출력되는 `nuboctl apply` 명령을 미리보기부터 실행한다.

```bash
git pull --ff-only
npm run server:stage
```
