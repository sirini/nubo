# 운영 로그·접속 기록·관리자 감사

## 보관 원칙

| 종류 | 기록 | 보관·삭제 | IP | 일일 한도 |
| --- | --- | --- | --- | --- |
| 방문자 접속 | 페이지 접속 시각·경로, 인증 UID(비회원 0) | 관리자 명시적 삭제까지 계속 보관 | 원문 | 100MiB |
| 관리자 감사 | 관리자 페이지 방문, API 실행 전·후, 점검·CSV·삭제 | 관리자 명시적 삭제까지 계속 보관 | 원문·출처 | 100MiB |
| 단기 운영 | 변경 요청·관리자 조회·HTTP 오류 | 기본 최근 7일, 자동 만료 | /24·/48 마스킹 또는 미보관 | 10MiB |

**방문자 접속과 관리자 감사에는 자동 만료가 없다.** 시작·저장·조회·CSV·정리 작업이나 탈퇴로
삭제하지 않는다. 3년 이상 된 기록도 그대로 조회·내보내기·통계에 사용한다. 기존 설치의
`NUBO_VISIT_LOG_DAYS=90`, `NUBO_AUDIT_LOG_DAYS=732` 등 값은 더 이상 읽거나 적용하지 않는다.
이미 이전 버전에서 삭제한 기록을 복원하는 기능은 아니다.

최소 3년 등 조직의 보존 지침은 관리자가 수동 삭제 전에 확인한다. 저장소는 계속 누적되므로
디스크 용량·권한·백업을 점검한다. 일일 한도는 기간에 따른 삭제·오래된 기록 덮어쓰기를 뜻하지 않는다.
방문 기록은 한도를 넘으면 새 기록을 생략하고 프로세스 기준 생략 수를 표시한다.
관리자 감사의 용량 초과·쓰기 실패·무결성 실패는 관리자 API 작업을 차단한다.

## 수집과 통계

최초 Nuxt 문서 렌더링은 서버, 이후 SPA 경로 변경·인증 상태 변경은 브라우저에서 기록한다.
최초 hydration은 중복 집계하지 않는다. UID는 요청 본문의 숫자가 아닌 토큰·활성 계정 검증 결과다.
서버 문서 요청의 만료·유효하지 않은 세션은 익명 접속으로 기록하고, 재인증에 따른 상태 변경은 별도 기록한다.
검색 경로의 검색어·비밀번호 변경 코드와 query·fragment는 제외한다. 본문·이메일·쿠키·토큰을 복사하지 않는다.

관리자 화면 경로는 감사에 `PAGE`·`page-visit`으로 남는다. 실제 업무 처리 결과는 API의
`intent`/`completed`·HTTP 상태·가능할 때 업무 코드를 함께 확인한다. HTTP 200만으로 업무 성공을 판단하지 않는다.
감사에는 확인 가능한 대상 회원 번호, CSV 제출 목적, 요청 상관관계 ID도 포함한다.

UTC 연도를 선택해 일/월/연 **페이지 접속 건수**를 확인한다. 순 방문자 수가 아니며 수동 삭제한
날짜는 통계에서도 제외된다. 오래된 연도의 조회에 보관 일수 제한을 적용하지 않는다.
위치 DB나 외부 IP 조회를 사용하지 않아 지역 통계는 제공하지 않는다.

SPA는 브라우저 차단·변조·실패로 누락될 수 있고 정적 캐시·API 직접 사용도 별도다.
수집 API는 접속지별 분당 120건 제한이 있다. 독립 Nginx·호스팅·시스템 접근 로그를 대체하지 않는다.
일반 문서 응답은 기록 장애로 차단하지 않는다. 보안부서 제출에는 필요한 독립 기록과 함께 사용한다.

## 관리자 콘솔·명시적 삭제

`/admin/logs`에서 활성 최고 관리자(현재 UID 1)가 유형·UTC 날짜별 최신 100건씩 조회한다.
전체 날짜 CSV는 점검·사고 대응·권한 있는 제출 중 목적을 선택한다. 조회·다운로드도 감사에 남고
UTF-8 BOM·CSV 인용·수식 시작 문자 무력화·no-store 응답을 적용한다. 내려받은 CSV와 외부 백업은
서버에서 삭제하지 않으므로 별도 보관·전달·파기를 관리한다.

방문자/감사 유형을 선택하면 **선택한 날짜 기록 영구 삭제**를 제공한다.

1. 과거 UTC 날짜와 기록 종류를 선택한다. 당일·미래 파일은 삭제하지 않는다.
2. 삭제 사유(조직 보관 정책·개인정보 처리 요청·테스트 정리)를 선택하고 날짜를 직접 재입력한다.
3. 보관 지침·대상·영구 삭제 확인에 체크한 뒤 삭제한다. 선택한 날짜의 파일 전체가 대상이다.
4. 삭제자·종류·대상 날짜·사유·요청 ID·실행 전후 결과는 당일의 HMAC 감사에 남는다.

API: `DELETE /admin/system/records/{visits|audit}?date=YYYY-MM-DD`, JSON
`{"confirmDate":"YYYY-MM-DD","reason":"retention-policy|privacy-request|test-cleanup"}`.
서버가 최고 관리자 권한·활성 계정·날짜 재입력·사유를 검증한다. 단기 운영 로그는 이 API의 대상이 아니다.
브라우저와 BFF 모두 삭제를 자동 재시도하지 않는다. 결과가 불명확하면 먼저 재조회·감사를 확인한다.

감사 파일은 삭제 전 무결성을 검증한다. 변조 파일을 정상인 것처럼 삭제하지 않는다.
데이터와 봉인을 지우되 `.integrity-key`와 다른 날짜는 보존한다. 중단 시 남은 `.seal.deleting`은
인증된 동일 날짜의 삭제 재요청으로 검증·정리한다. 이때 과거 날짜 읽기가 실패해도 현재 백엔드의
수동 삭제 모드를 확인할 수 있으면 콘솔의 삭제 확인란을 유지한다. 임의의 파일 변조나 키 유실은
서버 운영자가 신뢰할 수 있는 백업으로 복구해야 한다.

관리자 감사 월별 점검 확인은 해당 월의 보관 파일을 검증하고 담당자·시각·월을 남긴다.
삭제된 날짜를 복원하거나 실제 업무 점검을 대신하지 않는다.

## 무결성·비공개 저장소

감사는 HMAC 연결·일별 봉인과 fsync를 사용한다. 조회·CSV에서도 전체 날짜의 순서·내용·끝부분
절단을 검증한다. 최초 의도 기록 실패 시 작업을 시작하지 않는다. 완료 기록 실패 시 503이며
작업이 이미 실행됐을 수 있다. 이를 무조건 재시도하지 않는다.

저장 디렉터리 0700·새 파일 0600, 공개 업로드 경로 및 그곳을 가리키는 심볼릭 링크는 시작 시 거부한다.
기본 `./security-logs`, 하위 `visits`와 `audit`. 한 디렉터리는 한 GOAPI 인스턴스가 사용한다.
감사 키가 유실된 기존 기록을 자동 삭제해 초기화하지 않는다. 키와 봉인을 포함해 안전하게 백업한다.
서버 권한으로 파일·봉인·키를 모두 삭제할 수 있는 공격까지 막는 독립 WORM 저장소는 아니다.
관리자가 과거 삭제 감사 파일 자체를 나중에 명시적으로 삭제할 수 있다는 점도 보관 지침에 반영한다.

## 프록시·설정·배포

`NUBO_TRUSTED_PROXY_CIDRS`로 명시한 직접 연결 프록시의 `X-Real-IP`만 신뢰한다.
임의의 X-Forwarded-For 첫 값과 /0 설정은 신뢰하지 않으며 IPv4-mapped IPv6도 정규화한다.
공식 Nginx는 `X-Real-IP $remote_addr`로 덮어쓴다. 로컬 Nginx/Nuxt 예:

```
NUBO_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
```

웹과 GOAPI 양쪽에 적용한다. 추가 로드밸런서는 Nginx real_ip와 신뢰 범위를 별도로 설정한다.
미설정 시 이용자 대신 프록시·loopback 주소일 수 있다. 주소 출처는 CSV에 포함한다.

- `NUBO_SECURITY_LOG_DIR`: 기본 `./security-logs`. 공식 systemd는 `/var/log/nubo/security`.
- `NUBO_SECURITY_LOG_DAYS=7`(1~90), `NUBO_SECURITY_LOG_MASKED_IP=true`: 단기 운영에만 적용.
- 방문자·감사는 보관 일수 설정이 없고 수동 삭제만 허용한다. 기존 두 보관기간 변수는 제거해도 된다.
- 공개 `/privacy/status` 및 웹 `/api/legal/status`는 활성 여부·`*LogManualDeletionOnly`와 보관 일수를
  제공한다. 수동 모드는 `retentionDays=0`, `manualDeletionOnly=true`다. 0일 후 삭제라는 의미가 아니다.
- 웹과 GOAPI를 함께 업데이트한다. DB migration은 없다. Nginx/systemd 자체 로그 정책은 별도다.
- 공식 바이너리는 GOAPI `./scripts/build-ubuntu22.sh`로만 생성하며 `dist/nubo-runtime/bin/goapi`에 둔다.

개인정보처리방침도 실제 백엔드 모드에 따라 무기한·명시적 삭제를 표시한다. 구버전이 유한 보관을
보고하면 그 일수를 표시하고, 백엔드가 미확인이면 외부 처리 없음으로 추정하지 않는다.
