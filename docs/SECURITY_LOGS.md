# 운영 로그·관리자 감사와 제출

## 기록 구분

기존 GOAPI `user_access_log`는 방문 통계용 회원 번호·방문 시각만 저장한다. IP 컬럼은 없고
계정 삭제 시 연결 기록이 삭제된다. Nginx·호스팅·systemd journal·기존 앱 오류 출력은 별도다.

이번에 두 종류의 비공개 파일 기록을 추가했다.

| 종류 | 기록 대상 | 기본 보존 | 주소 | 저장 한도 |
| --- | --- | --- | --- | --- |
| 단기 운영 | 변경 요청, 관리자 조회, HTTP 오류 | UTC 최근 7일 | IPv4 /24·IPv6 /48 마스킹 또는 미보관 | 일 10MiB |
| 관리자 감사 | 활성 최고 관리자 API 요청의 실행 전·후 | UTC 최근 732일 | 접속지 원문, 출처 구분 | 일 100MiB |

공통: UTC 시각, HTTP 방식, 등록된 경로 패턴·HTTP 결과·소요시간·인증된 내부 회원 번호.
감사 추가: 요청 상관관계 ID, 단계, 표준 응답의 업무 결과 코드, 요청·응답에서 확인 가능한
대상 회원 번호, CSV 제출 목적. 일반 GET 열람 전체를 추적하지 않는다. 비밀번호·토큰·쿠키·
이메일·검색어·본문을 로그에 복사하지 않는다. 대상 회원 식별을 위해 요청·응답에서 숫자 회원
번호만 추출한다. 대상 번호가 반환되지 않는 작업은 자동 식별 범위 밖이다.

인증되지 않은 요청이나 공개 로그인 처리는 회원 번호가 0일 수 있다. HTTP 200은 업무 결과
성공을 보장하지 않으므로 감사에는 가능할 때 업무 코드도 별도 표시한다.

## 대한민국 기준을 고려한 관리자 감사

[개인정보의 안전성 확보조치 기준](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulId=73493&efYd=0)
(시행 2026-07-01)의 개인정보처리시스템 접속기록 보존·점검·안전 보관 취지를 반영했다.
정보주체 본인의 일반 이용 기록과 개인정보를 처리하는 관리자의 기록은 구분한다.
기본 732일은 UTC 날짜 경계와 윤년을 고려해 2년 이상을 확보하는 보수적인 설정이다.
1년 대상과 2년 대상의 적용 여부, 정기 점검 주기·사후 조치 등은 운영처의 처리 규모·정보 유형과
내부관리계획에 따라 확인해야 한다. 제품의 월별 확인 기능이 실제 점검을 대신하지 않는다.

감사 의도(intent) 기록이 실패하면 관리자 작업을 시작하지 않는다. 실행 후 결과 기록 실패 시
503을 반환하며 작업이 이미 실행되었을 수 있음을 알린다. 이때 무조건 재시도하지 말고 서버
상태와 실제 처리 결과를 확인해야 한다. 일반 이용자의 서비스 요청은 단기 로그 실패로 차단하지 않는다.

관리자 감사는 HMAC 연결과 일별 봉인 파일로 순서·내용·끝부분 절단을 확인한다. 쓰기 시 fsync를
하고 조회·내보내기에서도 검증한다. 검증이 실패한 파일을 정상 CSV인 것처럼 내보내지 않는다.
`.integrity-key`를 포함한 감사 디렉터리를 제한된 권한으로 보관·백업해야 한다.
키 분실·부분 기록·봉인 불일치 시 자동으로 이력을 재작성하지 않고 관리 작업을 차단하므로
신뢰할 수 있는 백업과 서버 측 복구 절차가 필요하다. 파일과 봉인·검증키를 모두 지울 수 있는
서버 권한 탈취까지 막는 독립 WORM 저장소는 아니다. 별도 접근통제·외부 백업을 마련해야 한다.

## IP와 신뢰 프록시

기본은 직접 연결 주소다. `NUBO_TRUSTED_PROXY_CIDRS`에 명시한 프록시에서 온 요청에 한해
`X-Real-IP`를 허용하며 그 외 입력과 `X-Forwarded-For`의 임의 첫 값을 신뢰하지 않는다.
전체 네트워크를 신뢰하는 /0 지정은 무시한다. IPv4-mapped IPv6도 정규화한다.

공식 Nginx는 `X-Real-IP $remote_addr`로 덮어쓴다. 이 구성에서 로컬 Nginx/Nuxt를 사용하는 예:

```
NUBO_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
```

같은 값을 웹과 GOAPI 실행 환경에 적용해야 한다. 웹 프록시는 검증한 주소만 백엔드로 다시 전달한다.
추가 로드밸런서가 있으면 Nginx의 real_ip 설정과 신뢰 범위를 따로 검토한다. 미설정 상태에서는
프록시·loopback 주소일 수 있으며 실제 이용자 IP라고 주장할 수 없다. 단기 로그는 위 주소를
마스킹하며 관리자 감사만 원문을 접근 제한하여 보관한다. 주소 출처도 CSV에 포함한다.

## 설정·보관

- `NUBO_SECURITY_LOG_DAYS=7` (1~90)
- `NUBO_SECURITY_LOG_MASKED_IP=true`: false면 단기 로그 주소 미보관
- `NUBO_AUDIT_LOG_DAYS=732` (367~732): 축소 전 적용 법령·내부 규정 검토
- 직접 실행: `NUBO_SECURITY_LOG_DIR` 미지정 시 `./security-logs`, 하위 `audit`가 관리자 감사
- 공식 systemd: `LogsDirectory=nubo`, mode 0700,
  `NUBO_SECURITY_LOG_DIR=/var/log/nubo/security`. 기존 설치는 새 unit도 적용해야 한다.
  systemd 환경 변수가 `.env`보다 우선하므로 경로 변경 시 unit도 함께 수정한다.
- 디렉터리 0700·새 파일 0600. 공개 업로드 경로와 그 안을 가리키는 심볼릭 링크는 시작 시 거부.
- 만료 삭제: 시작·기록·조회·매시간. 중지 중에는 다음 시작 시 삭제.
- 한 디렉터리는 한 GOAPI 인스턴스가 사용한다. 복수 인스턴스는 분리한다.
- 단기 한도 초과는 생략 건수를 표시한다. 관리자 감사 한도 초과·오류·변조는 관리 작업을 차단한다.
  서버 운영자가 비공개 저장소의 여유 공간·권한과 백업을 복구해야 한다.

## 관리자 조회·CSV·점검

`/admin/logs`에서 유형·UTC 날짜별 최신 100건 단위로 조회한다. 활성 최고 관리자 UID 1만
서버에서 허용한다. 기록 유형별 해당 날짜 전체를 CSV로 내보내며 목적을 점검·사고 대응·
권한 있는 기관 제출 중 선택한다. 목적과 내보내기 자체가 감사에 기록된다.
의도 기록은 내보내는 파일에 포함될 수 있고 완료 기록은 다음 조회에서 확인한다.

UTF-8 BOM·표준 CSV 인용과 수식 시작 문자 무력화를 적용하고 응답은 no-store다.
다운로드한 파일은 서버 자동 파기 대상이 아니므로 수신자 권한·안전한 전달·별도 파기일을 정한다.
관리자 감사 화면에서 월을 선택해 실제 점검과 다운로드 사유 확인을 마친 뒤 확인을 남길 수 있다.
확인 시 해당 월 보관 파일의 무결성을 검증하고 관리자·시각·대상 월을 기록한다.

## 정책과 외부 연동 상태

공개 `/goapi/privacy/status`는 업체명·AI 사용 여부·로그 사용/일수/마스킹·감사 일수만 반환한다.
키·경로·계정 식별자는 반환하지 않으며 웹도 허용 목록으로 제한한다. 백엔드가 구버전이거나
연결되지 않으면 ‘미확인’으로 표시하고 외부 처리 없음이라고 추정하지 않는다.
기본 기능에 업체가 설정되지 않았을 때만 위탁·연동 없음으로 표시한다. 운영자가 계약한 호스팅이나
추가 플러그인은 별도 공개 상세를 따르므로 모든 외부 계약이 없다고 자동 보증하지 않는다.

OpenAI는 키·명시적 활성화·생성 수가 유효할 때만 사용 중으로 표시한다. 실제로 작은 썸네일과
설명 프롬프트를 전송하고 생성 텍스트를 검색에 사용한다. 원본·계정 이메일·비밀번호를 설명
요청에 첨부하지 않는다. 썸네일 자체는 익명화를 뜻하지 않는다. 업체별 처리 조건·국외 이전 근거·
안내 및 필요한 동의는 운영처가 확인해야 한다. 기능이 기본 비활성이라는 사실이 활성화 후의
법적 절차까지 면제하지 않는다.

## 배포와 확인

웹·새 GOAPI·systemd unit을 함께 반영한다. DB 스키마 변경은 없다.
공식 바이너리는 형제 GOAPI의 `./scripts/build-ubuntu22.sh`로 생성하고 `dist/nubo-runtime`에 둔다.
보안 테스트는 권한·민감값 배제·마스킹·신뢰 프록시·만료·용량·CSV 인용·변조/절단 탐지와
변조 시 관리자 작업 차단을 확인한다. 법률 적합성 인증이나 실제 업무 점검을 뜻하지는 않는다.
